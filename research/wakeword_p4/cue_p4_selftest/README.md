# 固定合成音的 ESP32-P4 数值自测

在 ESP-IDF 5.5.4 环境中从本目录执行下列命令编译独立应用。

```sh
idf.py set-target esp32p4
idf.py build
```

应用嵌入研究分支的 v3 WAV，CMake 在编译前验证 SHA256。依次送入 81600 个零样本、整条 v3、32160 个零样本和同一条 v3，全程保持匹配器状态。串口时间以第一条 WAV 的样本 0 为起点。预期恰好两次事件，位值均为 2，时刻分别为 13214 和 66574。日志同时报告每 480 样本的最慢处理时间、达到 30 ms 的块数和最低内部空闲堆。

ESP32-P4 QEMU 已启动这份应用并实跑通过。模拟器记录的最慢块为 2042 微秒，状态 6888 字节。整机麦克风、音频前处理、C161 解释器并发开销、队列和通话首词需另用面板固件测量。Mac 可将相同 WAV 与事件时钟用于现有测试入口。[QEMU 串口原件](../results/4090-c161-cue-p4-selftest-uart-v1.log) · [构建与运行身份](../results/4090-c161-cue-p4-selftest-v1.json)

v5 可从同一目录单独构建。先在 ESP-IDF 5.5.4 环境选择 esp32p4，再通过独立的构建目录启用远场首句样本。

```sh
idf.py -B build-v5 -DIDF_TARGET=esp32p4 -DNYX_CUE_SELFTEST_V5=ON build
```

应用将远场 v5 接命令的 WAV 播放两遍，间隔 32163 样本。两次预期事件在 102932、278036，位值均为 8。首次命令首音素对应输入时钟 106539。P4 QEMU 实际运行得到两次预期事件，最慢 480 样本块为 424 µs，零个块达到 30 ms；该数值来自独立匹配器测试应用。[v5 串口](../results/4090-c161-coded-cue-p4-v5-uart.log) · [v5 固件身份和回放](../results/4090-c161-coded-cue-p4-v5.json)
