# Mac/P4 explicit-cache integration supplement

Main was inspected at `7955dc2bfea71aa99d786aee0feb75ed30f08732`. `components/panel_wake_runtime/panel_wake_runtime.cpp` lines99–111 enforce one input `[1,3,40]` and one UINT8 probability output. B40/history require eight inputs/eight outputs, chunk `[1,3,1,40]`, seven model-specific INT8 caches and signed probability. The existing runtime therefore cannot load these handoff models by replacing the embedded model bytes alone.

`explicit_cache_bytes_v1.h` supplies three dependency-free C++11 operations for the existing frozen ABI: real-zero cache reset using each tensor's zero point; byte-exact cache feedback only when input/output scales, zero points and sizes match; signed probability conversion to the UINT8 code consumed by the existing portable detector. It allocates nothing and performs no inference. Caller still verifies tensor names, shapes/types and original model SHA; never assume tensor-index order is cache order. The original handoff ABI manifests provide the names/indices.

For each B40/history interpreter, allocate seven dedicated retained cache input buffers, independent of the other models and of output arena storage. At complete stream initialization, reset each buffer using its own metadata. On every 480-sample call, quantize the shared float frontend features using that model's own chunk scale/zero, copy its retained buffers into the seven input tensors, and invoke. After successful Invoke, convert its signed probability and feed the portable detector once at the shared native step; copy all seven cache outputs into that model's dedicated retained buffers for the next call. Do not reset at clip boundaries or between zero-PCM prime and speech. Do not feed arbitration on an Invoke/metadata failure.

The helpers reject any future cache ABI needing requantization; they do not implement it silently. With these frozen models every corresponding cache pair permits byte-exact feedback. C161 retains its separate internal variable-state lifecycle and UINT8 output path; do not apply signed+128 conversion to C161. Multi-interpreter construction, operator registration, failure cleanup, scheduling and opt-in firmware selection remain Mac integration work. Existing `c161_binary40_history_events_v1.h` owns detector/rearm/shared cooldown/priority behavior; this supplement changes none of it.

`check_explicit_cache_bytes_v1.py` builds/runs a temporary C++11 executable against all14 cache pairs from the original ABI reports: all256 source byte values, real-zero reset, wrong scale/zero/size/null rejection without mutation, all256 signed probability codes and invalid-scale rejection. No permanent binary or PCM is added. This is an adapter check, not TFLM/P4 numerical evidence.
